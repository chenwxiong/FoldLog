# 计数与姿态展示规则

版本：v0.5，2026-10-23。计数及半开 1 秒规则不变。用户已同意先做普通 App，当前已创建原生体验版及计数逻辑测试；真实 Duo 开合与内外屏切换仍待真机验证。

## 1. 已确认口径

分别统计三类事件，每类都有今日次数和自开始记录以来的累计次数。

| 动作 | 计数结果 |
| --- | --- |
| 半开 → 合拢 | 合拢 +1，产品文案可称“折叠 +1” |
| 全开 → 合拢 | 合拢 +1 |
| 合拢 → 半开，连续停留满 1 秒 | 半开 +1 |
| 合拢 → 全开 | 全开 +1 |
| 半开 → 全开 | 全开 +1，无需先达到半开计数阈值 |

**半开连续停留阈值固定为 1 秒，已由用户确定。** 它是 App 的业务规则，和 Apple 用来划分合拢、半开、全开的角度边界是两回事。

按用户当前列出的计数方向，全开 → 半开只切换显示，不增加半开次数；回到全开则全开 +1。若以后需要把“从全开收回并停留半开”也计为一次半开，需要明确修改这一条。

## 2. 经过半开与停留半开

合拢到全开的途中，系统可能先报告半开。不能仅因收到这个中间状态就立刻增加半开次数。

- **停留不足 1 秒**：不记半开，随后全开只记全开 +1；随后合拢只记合拢 +1。
- **连续停留达到或超过 1 秒**：半开 +1；同一次停留保持多久都只计一次。
- **半开已计数后再全开**：全开另加 1，之前的半开不撤销；这是先停留半开、再进入全开的两项记录。
- **没有收到中间半开，直接收到合拢 → 全开**：只记全开 +1，不补造半开事件。

半开页显示与半开计数分别处理：进入半开状态时就可以切到内屏半开页，计数满 1 秒才增加。页面可显示“当前半开”，但不能把计时尚未成立的次数提前算入主数字或目标进度。

## 3. 完整状态转移表

| 前一有效状态 | 当前状态 | 合拢增量 | 半开增量 | 全开增量 | 上下文处理 |
| --- | --- | --- | --- | --- | --- |
| 合拢 | 合拢 | 0 | 0 | 0 | 重复回调不计数 |
| 合拢 | 半开 | 0 | 待确认 | 0 | 从首次进入半开开始计时 |
| 合拢 | 全开 | 0 | 0 | 1 | 直接确认全开 |
| 半开 | 合拢 | 1 | 不新增 | 0 | 未满 1 秒取消半开；已满 1 秒保留既有记录 |
| 半开 | 半开 | 0 | 达到 1 秒时最多 1 | 0 | 仅合拢发起的半开具备计时资格；重复回调不重置计时 |
| 半开 | 全开 | 0 | 不新增 | 1 | 未满 1 秒取消半开；已确认半开保留 |
| 全开 | 合拢 | 1 | 0 | 0 | 确认合拢 |
| 全开 | 半开 | 0 | 0 | 0 | 展示半开页，不启动新的半开计数计时 |
| 全开 | 全开 | 0 | 0 | 0 | 重复回调不计数 |
| 未知 / 无基线 | 任一有效状态 | 0 | 0 | 0 | 只建立基线，初始半开不启动计数计时 |
| 任一状态 | nil / unknown / 覆盖中断 | 0 | 0 | 0 | 取消待确认计时，恢复后重新建立基线 |

“不新增半开”不代表撤销此前已成立的半开计数。真实全开 → 半开 → 全开的转移按当前规则会再记一次全开；回调重复和真正的状态转移需要区分。

## 4. 三种姿态的首页

| 当前姿态 | 显示屏幕 | 主统计 | 目标区域 |
| --- | --- | --- | --- |
| 合拢 | 外屏 | 今日折叠次数；累计折叠次数 | 展开目标，含半开与全开 |
| 半开 | 内屏 | 今日半开次数；累计半开次数 | 折叠目标 |
| 全开 | 内屏 | 今日全开次数；累计全开次数 | 折叠目标 |

半开页和全开页引用同一个折叠目标。屏幕切换只改变展示方式，不重置目标、不清空数据，也不因为页面出现再记一次事件。历史页仍可手动选择三类指标，不被当前姿态强制切换。

这里的外屏、内屏指 App 随系统切换后的前台界面；屏幕接管、合拢瞬间事件交付及场景重建行为须真机验证。App 从其他场景回来时的当前姿态是快照，不是历史动作。

### Duo 全局右侧纵向栏

最新决策：用户已接受先做普通 App，此系统栏不纳入当前体验版。以下保留此前需求与核查结论，不再作为本轮 UI 的阻塞项。

用户已明确：切换到其他 App 后，系统右侧纵向栏仍常驻显示折叠、展开次数。此前按 App 内工具栏设计的入口不能满足此要求。

截至本次官方文档及 iOS 27.1 SDK 核查，尚未找到可实现该全局栏位的公开接口，保留为未满足需求。实时活动与小组件仅列为备选展示渠道，未替用户选定，也不能据此承诺后台持续采集。主页面继续沿用三姿态的数字与目标规则；展开合并口径未定前，不将半开与全开直接相加。范围与证据见 [全局右侧栏需求与可行性](纵向工具栏方案.md)。

### 展开目标的配置仍待确定

用户已经明确合拢时展示“展开目标（半开、全开）”。建议先设计为半开、全开两项独立进度；尚未确认是否分设目标值，不能将此建议当成最终配置。

若以后改成一个合并目标，需明确统计的是：

- 两类姿态事件之和：半开满 1 秒后再全开会贡献 2 次。
- 每次从合拢打开的去重次数：上述过程贡献 1 次，需要额外定义展开会话，不能直接使用半开与全开之和。

在口径确定前，分别保存三类次数，不新增含义不明的“展开总次数”。

## 5. 计时与数据要求

1. 合拢 → 半开时，保存单调时钟的开始时间；到开始时间 +1 秒确认一次半开。
2. 不要求每秒有固定数量的回调。重复半开样本不能重启计时；持续半开也不能每秒加一次。
3. 到达 1 秒前收到全开、合拢或失去有效覆盖，取消待确认半开。
4. 恰好满 1 秒算半开；处理下一条有效转移前，若连续半开已达到 1 秒但定时回调尚未调度，也应先按时间顺序确认半开，再处理转移，确保结果不因定时器调度顺序而变。
5. 第 4 条只用于已连续观测的有效区间。缺口后的快照不能用来补足半开停留时间；观测中断后不接着旧计时累计。
6. 多视图、内外屏和多回调入口共用单一计数上下文，分类事件按唯一 ID 保存，不依赖页面各自加次数。
7. 原始状态进入时间与计数确认时间分别保存。按确认时间归属统计日；半开确认在午夜后，则计入新一天。
8. 计数口径保存版本号。未来若改停留阈值，不默默改写旧数据；当前只有规划，尚无实际旧版本数据迁移。

“合拢→半开满 1 秒”是观测到的业务条件。传感器更新频率、回调延迟及合拢时是否丢失数据仍须实测，不因软件计时精确就宣称物理姿态测量具有同样精度。

## 6. 后续实现的验收示例

以下数字均为单段连续有效观测的增量；不是实际测试结果。

| 输入过程 | 合拢 | 半开 | 全开 |
| --- | --- | --- | --- |
| 合拢 → 半开 0.8 秒 → 全开 → 合拢 | 1 | 0 | 1 |
| 合拢 → 半开 1.0 秒 → 全开 → 合拢 | 1 | 1 | 1 |
| 合拢 → 半开 1.5 秒 → 合拢 | 1 | 1 | 0 |
| 合拢 → 半开 0.5 秒 → 合拢 | 1 | 0 | 0 |
| 合拢 → 半开 10 秒（未离开） | 0 | 1 | 0 |
| 合拢 → 全开（没有中间回调） | 0 | 0 | 1 |
| 全开 → 半开 2 秒 → 全开 | 0 | 0 | 1 |
| 合拢 → 半开满 1 秒 → 全开 → 半开 → 全开 | 0 | 1 | 2 |
| 首次进入时已半开，并继续保持 5 秒 | 0 | 0 | 0 |
| 合拢 → 半开 0.7 秒 → 缺口 → 恢复时半开，再等 0.4 秒 | 0 | 0 | 0 |

额外验收项：恰好 1 秒的边界、定时与转移先后顺序、半开重复回调不重置计时、三类事件跨日、存储失败重试、内外屏切换不重复记录。
