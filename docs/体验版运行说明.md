# 折记 · 原生 App 体验版

2026-10-24，版本 0.1。工作名称仍可修改。用户先确认普通 App，随后增加桌面 / 锁屏小组件，当前交付覆盖计数、目标、页面流程与组件展示。

本轮更新为黑白金配色、SF Symbols 和原生系统导航 / 表单。浅色采用白卡片与深金色，深色采用黑底与浅金色；今日和历史按可用宽度切换单双列，设置在宽屏展示左侧分类与右侧详情，窄屏和辅助字号下采用纵向表单。设计依据和 Duo 专项验证边界见 [UI 视觉规范](UI视觉规范.md)。

## 如何运行

产品仅支持 iPhone Duo，发布版本要求 iOS 27.1+。使用 Xcode 27.1 或更新版本打开根目录 `FoldLog.xcodeproj`，选择 `FoldLog` scheme 和 iPhone Duo；真机安装需要在 Signing & Capabilities 中选择自己的开发团队，无需第三方依赖。

优先在 iOS 27.1 的 Duo 模拟器检查实际布局。开发期间也可双击 `scripts/run-preview.command` 自动构建并打开普通 iPhone 模拟器的设计预览。手动使用普通模拟器时，需要在 Debug 的启动参数里添加 `--design-preview`，否则显示“仅支持 iPhone Duo”。该参数只在 Debug 模拟器生效；Release 的系统要求与机型限制不会由参数绕过。具体范围见 [仅 Duo 兼容范围](仅Duo兼容范围.md)。

设计预览初次启动默认进入演示模式，次数从 0 开始；受支持 Duo 初次启动默认使用设备记录。已有档案与模式选择继续保留。建议在预览中依次体验：

1. 在“今日”点击“半开”，连续等待 1 秒，看到半开次数增加。
2. 点击“全开”，全开另加 1；点击“合拢”，折叠加 1。
3. 在“设置”开启并输入目标，再返回今日查看目标展示。
4. 到“历史”切换折叠 / 半开 / 全开，查看每日明细；关闭并重新打开 App，记录会保留。

快速经过半开不足 1 秒不会计入半开。半开已计入后再全开，两类分别累计。重复点击相同姿态不增加次数。

## 当前实现

| 模块 | 体验版范围 |
| --- | --- |
| 今日 | 依当前姿态切换主数字；今日与累计分类型显示；合拢展示半开 / 全开目标，半开 / 全开展示同一个折叠目标 |
| 模拟开合 | 合拢、半开、全开按钮；独立 1 秒半开计时；演示记录明确标识 |
| 每日目标 | 三类独立、默认关闭；作为个人每日上限；首次可当天生效，后续修改默认次日生效；关闭立即生效 |
| 历史 | 7 / 30 天、类型切换、已记录次数图表、每日详情和事件时间；无记录日显示“—” |
| 数据 | 本地 JSON 原子保存；演示和设备档案分开；导出当前档案；清空需确认 |
| 外观 | 黑白金、SF Symbols、原生导航与表单；默认 / 深色 / 着色原创 App 图标；系统字号及 Duo 可用空间自适应 |
| 小组件 | 桌面仅小号，锁屏圆形 / 单行；今日折叠 / 剩余两种入口；原子共享统计、跨日时间线与目标跳转 |
| 设备入口 | 使用已有公开铰链回调接入状态机；iOS 27.1+ 才启用；不可用时说明原因，可切回演示 |

普通模拟器通过演示按钮体验姿态，不能模拟真实 Duo 铰链传感器。内屏 / 外屏目前是相应的信息布局预览，实际系统切屏与事件连续性尚未验证。设备模式仅显示已收到并保存的前台记录，不承诺全天、后台、锁屏、退出后的持续采集。

本次没有接入全局右侧栏、实时活动、账号、云同步、付费或商店发布。JSON 导入恢复尚未实现，导出文件可留存但当前体验版不能在界面中导入；不能据此承诺卸载后的自动恢复。

小组件添加方法、共享容器签名配置与刷新边界见 [桌面与锁屏小组件](桌面与锁屏小组件.md)。

## 工程结构

- `FoldLog/Core/`：独立计数状态机、档案、目标版本与存储逻辑，使用 Foundation。
- `FoldLog/AppStore.swift`：单一计数入口、计时、本地读写与模式切换。
- `FoldLog/Views/`：今日、历史、设置、组件样式预览及共用视图。
- `FoldLogWidgets/`：WidgetKit 扩展、时间线与两种系统组件入口。
- `FoldLog/Widgets/`：App 与扩展共用的原生组件视图。
- `FoldLogUITests/`：原生界面流程与截图检查。
- `Tests/`：计数边界与存储测试，可通过 `swift test` 执行。
- `scripts/generate-project.py`：生成可直接打开的 Xcode 工程；工程已提供，无需先执行。

## 验证命令

在项目根目录执行：

```sh
swift test
xcodebuild -project FoldLog.xcodeproj -scheme FoldLog \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build CODE_SIGN_IDENTITY=- build
```

界面测试须指定已安装运行时对应的模拟器：

```sh
xcodebuild -project FoldLog.xcodeproj -scheme FoldLog \
  -destination 'platform=iOS Simulator,name=FoldLog Preview' \
  -derivedDataPath build CODE_SIGN_IDENTITY=- test
```

测试使用独立的 `FoldLogUITests` 数据目录，不清空普通运行的演示或设备档案。

最新 `swift test` 共 17 项通过，包含计数、存储、Duo 兼容策略和 8 项小组件数据检查；非 Duo 拦截、预览中的计数保存、记录模式隔离 3 项界面补验通过。此前黑白金界面的 5 项完整流程在普通 iPhone 模拟器预览通过，小屏的目标 / 历史、最大字号与横竖屏等 3 项专项检查通过；这些检查不代表支持普通机型。最新 Debug 模拟器与关闭签名的 Release 真机目标编译通过。测试来源和精选截图见 [验证记录](../artifacts/validation.md)、[界面预览](../artifacts/preview.png)。

启动脚本已成功构建、安装和启动普通演示 App。当前 Xcode 27.1 使用 Device Hub 作为设备预览入口；打开后选择 `FoldLog Preview` 即可体验。真机能力仍独立验收，模拟器上的按钮与测试通过不能替代真实开合验证。

## 上架前的真机验证

Apple [审核指南 2.1(a)](https://developer.apple.com/app-store/review/guidelines/#app-completeness) 明确要求提交前在设备上测试缺陷与稳定性（“tested on-device for bugs and stability”）。提交通常没有统一的真机测试报告上传步骤，但这不免除真机测试要求。

折记需要在支持的真机上验证真实开合计数、半开满 1 秒规则、内外屏连续性、锁屏 / 后台再返回，以及 App Group 签名和组件刷新。当前模拟器结果不能证明这些硬件行为已通过；可由持有支持设备的测试者完成验证，无需开发者本人拥有设备。
