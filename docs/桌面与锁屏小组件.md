# 桌面与锁屏小组件

2026-10-24。用户追加桌面 / 锁屏展示后，新增原生 WidgetKit 扩展。

## 能看到什么

按用户最新要求，合并为一个“今日折叠”组件，同时显示已记录、剩余与上限；桌面仅支持系统小号，锁屏支持圆形和时间上方的单行形式。设置 → 小组件 → 桌面与锁屏小组件可预览当前记录，或选择目标内、未设目标、达到上限、超出上限、大数字和待同步的示例；示例明确标识且不写入记录。

桌面以已折叠次数为主数字，下一行用金色突出剩余次数，右侧显示个人上限；细进度条表示已使用的比例。上限达到五位数时，将上限移至底行，给剩余数字留出整行空间，避免六位数截断。未设目标时剩余为“—”，不显示进度条；达到或超出时剩余保持 0，同时明确显示达到上限或超出次数。锁屏圆形同时呈现当前次数与“余 ×”，单行呈现“折叠 × · 余 ×”。完整数值与状态通过 VoiceOver 标签提供。

折叠只统计进入合拢的已保存事件，半开、全开不会加到该数字中。剩余 = max(每日上限 − 今日折叠, 0)。未设上限显示“未设置目标”和“—”；达到上限显示“已达上限”，超过则显示超出次数，原计数继续增加。

小组件跟随 App 当前记录来源；演示记录带“演示”标识。切换来源、保存事件、保存目标、清空当前模式、重试读档及前后台切换时，App 会原子写入共享统计并请求刷新。通常只需打开 App 一次，再添加组件。

## 如何添加

- 桌面：长按空白处 → 编辑 → 添加小组件 → 搜索“折记” → 选择“今日折叠”。
- 锁屏：长按锁屏 → 自定 → 锁定屏幕 → 点按时间上方或下方的组件区域 → 选择“折记”。
- 轻点整个组件打开今日，在 App 中调整折叠目标。小号组件使用一个整体点击入口。

统一组件沿用 `FoldLog.Count` kind，原“今日折叠”挂载可继续使用；此前开发版若添加过独立的“剩余折叠”，需改为添加统一组件。扩展仅注册一个 kind，不再让用户在两种同类统计之间选择。

## 数据与刷新

原始事件与历史目标继续保存在 App 原来的私有目录，没有迁移或覆盖。App Group 中仅放一个版本化的今日折叠统计快照和折叠目标版本，扩展不修改档案，也不独立采集姿态。

时间线使用档案统计时区的 Calendar 生成未来七天的午夜条目，跨日归零并应用该日生效的目标，兼容夏令时。App 当日尚未同步时，桌面显示“今日尚未同步”；读档失败显示“—”并引导打开 App，保存失败则保留最后已保存数字并显示暂停。重启设备后共享文件需解锁一次才能读取。

事件保存后会调用 `WidgetCenter.reloadTimelines`。扩展还请求约 30 分钟后的刷新；缺数据时约 15 分钟后重试。这些是刷新请求，系统根据预算和使用情况安排，不能保证每次折叠立即出现在桌面或锁屏。小组件不能补齐 App 后台、锁屏、退出期间未采集的次数。

## 工程与签名

`FoldLogWidgets` 已作为扩展目标嵌入主 App，两者共享 `FoldLog/Core` 与 `FoldLog/Widgets` 源码。共享组为 `group.app.foldlog.preview`，两份 entitlements 和工程的 App Groups capability 已配置。扩展 Info.plist 声明 `com.apple.widgetkit-extension`，App 注册 `foldlog://today` 与 `foldlog://goal/closed`。

模拟器需保留临时签名才能分配共享容器：

```sh
xcodebuild -project FoldLog.xcodeproj -scheme FoldLog \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build CODE_SIGN_IDENTITY=- build
```

`CODE_SIGNING_ALLOWED=NO` 可用于编译检查，但安装该未签名产物不会配置 App Group。启动预览脚本已改为使用临时签名。

真机使用时，为 App 与扩展选择相同开发团队，并确保该团队已注册两者的 bundle ID 和上述 App Group。发布要求仍为 iPhone Duo / iOS 27.1+；Debug 的普通模拟器仅用于设计验证。

## 验证

`swift test` 包含 8 项组件数据测试，覆盖折叠口径、未设 / 达到 / 超限、次日目标、跨日、夏令时、来源隔离、清空、损坏数据与链接路由。原生界面回归和截图结果见 [验证记录](../artifacts/validation.md)。

普通 UI 测试不写入组件共享数据；组件联调测试使用独立 App 档案和显式 `--widget-integration-testing` 参数，在结束后重新正常打开 App 即可恢复其真实共享投影。测试中的模式切换不会再改变正常 App 的来源偏好。
