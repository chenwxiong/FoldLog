# Duo 全局右侧栏需求与可行性

版本 v0.4，2026-10-23。用户已明确：需要切换到其他 App 后，仍常驻显示的系统右侧纵向栏。v0.3 的 App 内工具栏方案不满足这一要求，本版据此修正范围。

**后续决策补充（规划 v0.5）：用户已接受先做普通 App 体验版。** 本文保留系统栏的调研依据；全局右侧栏不再是本轮 UI 的进入门槛，实时活动与小组件也未纳入本轮实现。

## 已确认的需求

- 在其他 App 使用期间，也能直接看到折叠与展开次数。
- 显示位置为 Duo 右侧纵向系统栏，期望持续可见。
- 保留今日、累计与目标的既有规划；半开连续停留满 1 秒才计数。

首版栏内默认显示今日次数是此前的设计建议，尚未单独确认。展开合并口径也未确定：半开满 1 秒后再全开，两类会各加 1，因此不能直接相加并称为打开手机的次数。可先用“折叠 32、半开 6、全开 24”表达信息需求；数字仅为示例，不代表已具备系统栏实现。

主页面继续按姿态显示：合拢时在外屏突出折叠次数与展开目标，半开 / 全开时在内屏突出相应次数与折叠目标。它和跨 App 系统栏是两个展示场景。

## 当前可行性结论

**截至本次核查，尚未找到允许第三方 App 向 Duo 跨 App 常驻右侧栏添加统计项的公开接口。当前不能把该需求作为可交付功能排期。**

依据为 Apple Developer 的纵向工具栏、ActivityKit、WidgetKit、Controls 文档及更新说明，以及本机 iOS 27.1 的公开 SDK 接口。此结论限定于此次核查，不把“未找到”表述为对所有未来系统能力的证明。尚未进行 Duo 真机界面验证。

| 公开能力 | 已核实的用途 | 对本需求的结论 |
| --- | --- | --- |
| SwiftUI / UIKit 原生纵向工具栏 | 配置本 App 的视图与导航容器工具栏 | 不提供向其他 App 或全局系统栏注入内容的依据 |
| Live Activities / ActivityKit | 在系统支持的位置展示活动信息，例如灵动岛和锁屏 | 可作为跨 App 查看信息的备选；不能指定为右侧常驻纵栏 |
| WidgetKit 小组件 | 在桌面、锁屏等支持的位置显示简要信息 | 不会随其他 App 保持悬浮；刷新由系统调度 |
| WidgetKit Controls | 在控制中心、锁屏、操作按钮等位置提供动作或开关 | 适合快捷入口；不提供任意常驻统计栏 |
| ExtensionKit | 在支持的宿主中呈现扩展内容 | 没有查到面向此全局右侧栏的公开扩展点；通用扩展框架本身不能证明该栏位可用 |

若固定右侧、跨 App、持续可见是必需条件，现阶段缺少可实施的公开方案。无需先开发完整 App 来证明这一文档层面的缺口；下一步可向 Apple 提交针对该栏位的开发者技术问题，本次尚未提交。

## 实时活动作为备选的边界

实时活动最接近“离开 App 仍能看见”，但它改变了用户指定的位置与持续方式，尚未获选定。

- 在支持的设备与系统状态下显示于灵动岛 / 锁屏；具体呈现、空间与并存活动由系统决定。
- 官方文档明确提到 iPhone Duo 上的灵动岛呈现可能受宽度限制，建议适配约 28 pt 直径圆形的紧凑内容。不能承诺三项数字始终同时可见；可在展开呈现中显示明细。
- 按官方文档，单次活动最多活跃 8 小时，也可能提前由用户或 App 结束；结束后锁屏最多再保留 4 小时。它不等于全天永久常驻，不能将反复续开当作已验证方案。
- 适用性仍需评估：实时活动用于跟踪有时间范围的事件或任务；全天累计统计是否有合适的活动场景，不能只因 API 可用就确定产品方案。
- 展示已保存的次数与实时取得铰链事件是两件事。ActivityKit 的显示和更新机制不提供本场景的持续铰链采集保证。

小组件适合快速查看最近已记录的数据，也应标注数据时间与覆盖缺口。WidgetKit 官方说明扩展即使在屏幕上可见，也不会持续运行；不能保证每次开合后立即刷新，更不能作为全天传感器监听器。

控制中心可另行评估为“打开统计详情”的快捷入口；它需要用户调出，并不满足常驻查看。

## 保留的 App 内工具栏研究

下列 API 已通过文档与 SDK 核查，但仅作为 App 内适配研究，不再列为已确认的首版系统栏实现：

| API | 能力与限制 |
| --- | --- |
| `ToolbarItem` | 放置本 App 的工具栏项及自定义内容 |
| `.axisBehavior(.verticalPreferred)` | 在横、纵栏均可用时优先纵栏；属于布局偏好 |
| `.toolbarVerticalBehavior(.automatic)` | 由系统根据设备和 App 状态决定是否使用纵栏 |
| `toolbarVerticalEdge` | 只读首选侧；由设备和 locale 决定；非空不保证此刻可见 |
| `.toolbarVerticalCompressionBehavior(.prefersToolbarItems)` | 空间不足时的内容保留偏好；不保证任意数字和字号完整显示 |

`research/VerticalBarAPIProbe.swift` 已通过 iOS 27.1 / arm64 类型检查；只是本 App 工具栏语法探针，未验证运行布局、跨 App 存续或传感器数据。此次只补充范围注释，未重复执行未改变的 API 调用。

如后续选定 App 内工具栏备选，再恢复相关交互细化：明确名称与读屏标签、Dynamic Type、至少 44×44 pt 点击区域、紧凑时通过菜单展示半开 / 全开明细。不能在当前范围中把该备选默认为用户已接受的降级。

## 后续开发的两项独立门槛

1. **全局展示**：取得可引用的右侧栏公开接口依据，或由用户选定灵动岛 / 锁屏 / 小组件等替代方向；单纯验证 App 内工具栏不满足此项。
2. **持续数据**：真机验证跨 App、后台、锁屏和退出期间的数据来源与回补能力；即使全局展示可见，也不能据此判定统计连续。

计数状态机与半开 1 秒规则保持不变；具体见 [计数与姿态展示规则](计数与姿态展示规则.md)。当前可继续进行数据源诊断，完整 UI 与发布承诺需同时考虑上述两项门槛。
